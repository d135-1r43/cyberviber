# cyberviber

Claude Code session manager for a 2.4" ESP32 touch display (ESP32-2432S024, 240×320). It lists all running Claude Code sessions, shows their state (needs you / ready / working / idle), and tapping one brings its terminal to the front: zellij or herdr pane, then the Tabby tab, Ghostty or kitty window.

Status: the Mac daemon, the browser simulator, the jump to the terminal, the USB link and the firmware with all five layouts and eleven themes work, and the backlight dims when nothing happens. Design and architecture are in [spec.md](spec.md); the layouts are in [design/index.html](design/index.html).

## Install (macOS)

From source (needs Go, e.g. `brew install go`):

```sh
go install github.com/d135-1r43/cyberviber/cmd/cyberviber@latest
~/go/bin/cyberviber install
```

Or download a binary from the [releases](https://github.com/d135-1r43/cyberviber/releases) (arm64, amd64, universal). The binaries are not notarized: run `xattr -d com.apple.quarantine cyberviber` after extracting.

`cyberviber install`:
- adds hooks to `~/.claude/settings.json`, keeping all other hooks. A backup is written once to `settings.json.cyberviber-backup`.
- sets `cyberviber statusline` as Claude Code's status line, unless you have your own. It prints nothing and reports each session's context usage to the daemon (the `ctx` bar in the btop layout).
- installs the launchd agent `dev.cyberviber.daemon`, which logs to `~/Library/Logs/cyberviber.log`.
- installs the Tabby plugin, if Tabby is present. Reload or restart Tabby once afterwards.

kitty is focused through its remote control. Add to `~/.config/kitty/kitty.conf` and restart kitty:

```
allow_remote_control socket-only
listen_on unix:/tmp/kitty
```

herdr and zellij need no setup: the daemon reads the pane from the session's environment and talks to the multiplexer directly.

`cyberviber uninstall` removes all of it, except the kitty lines, which you added yourself.

## Install (Linux, Hyprland)

Tested on Omarchy (Arch, Hyprland, foot, zellij); kitty and herdr are unit-tested. Needs `ss` (iproute2) and `hyprctl`.

```sh
go install github.com/d135-1r43/cyberviber/cmd/cyberviber@latest   # or a linux release binary
~/go/bin/cyberviber install
sudo usermod -aG uucp "$USER"   # access to /dev/ttyUSB0 (Arch; Debian/Ubuntu: dialout), log in again
```

`cyberviber install` does the same as on macOS, but runs the daemon as the systemd user service `cyberviber.service` (logs: `journalctl --user -u cyberviber`). For kitty, add the two remote-control lines above (`listen_on unix:@kitty` also works on Linux). The terminal is raised with `hyprctl dispatch hl.dsp.focus({ window = "pid:<terminal>" })` (Hyprland 0.57+; older versions get `focuswindow pid:<terminal>`), which also switches to its workspace; other compositors only get the pane and tab focused, not the window. Terminals without a remote control of their own (foot, alacritty, Ghostty on Linux, …) are focused by their Hyprland window; when several windows share one process (`foot --server`, Ghostty), cyberviber briefly sets a unique title on the session's TTY to find the right one.


```sh
cyberviber status    # session table
cyberviber sim       # browser simulator with live sessions: http://127.0.0.1:7337/
cyberviber layout tiling       # waybar, tiling, btop, walker, hyprlock ('cyberviber layout' shows the current one)
cyberviber theme nord          # 'cyberviber theme list' lists all eleven
cyberviber brightness 60       # backlight in percent
cyberviber usb bottom          # turn the screen so the USB port points down (or: top)
cyberviber dim 15              # dim after 15 min without activity ('off' never dims)
cyberviber screenshot out.png  # the device screen as PNG (~20 s)
cyberviber release   # free the device's serial port for 60 s (e.g. to flash it)
cyberviber version
```

Config: `~/.config/cyberviber/config.toml` (`port`, `idle_after`, `serial`, `baud`).

## Firmware

Board: ESP32-2432S024R (2.4" TFT, XPT2046 resistive touch, CH340 USB). [PlatformIO](https://platformio.org) builds and flashes it:

```sh
uv tool install platformio                       # or: pipx install platformio
cyberviber release 120                           # the daemon frees the port
pio run -d firmware -t upload
cyberviber release 1                             # reattach right away
```

On first boot the device asks for a touch calibration (tap the four arrow tips); it is kept in flash. Hold a finger on the screen while plugging it in to calibrate again. `pio run -d firmware -e cyd24r-touchlog` builds a variant that reports raw touch points to the daemon log. Fonts are generated by `firmware/tools/gen-fonts.sh`.

## Continue on another Mac

```sh
git clone git@github.com:d135-1r43/cyberviber.git && cd cyberviber
go test ./...
go install ./cmd/cyberviber && ~/go/bin/cyberviber install   # hooks, daemon, Tabby plugin
# reload/restart Tabby once, then:
~/go/bin/cyberviber sim                                      # http://127.0.0.1:7337/
```

On the old Mac, run `~/go/bin/cyberviber uninstall` if it should stop reporting.

With [cyd-launcher](https://github.com/MiggiV2/cyd-launcher) the board can run other apps too. When one of them says hello as itself, the daemon lets go of the serial port so that app's host program (e.g. [cyd-pcstats](https://github.com/MiggiV2/cyd-pcstats)) can open it, and picks it up again once cyberviber is back.

On the device: swipe left/right or press BOOT to cycle layouts, long-press the top bar (or the header of the layout) for the settings screen. Layout, theme, brightness, the dim timeout and the orientation (USB port at the top or bottom, always portrait) are kept on the device. After the dim timeout (default 10 min) without a touch the backlight dims; a touch wakes it (that touch does nothing else), and so does a session that newly needs you.

Open questions are in spec §7.
